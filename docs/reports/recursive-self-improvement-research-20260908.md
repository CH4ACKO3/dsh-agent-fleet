# 递归自进化：研究线索、可核验证据与 Fleet 的创新空间

调查时间：2026-09-08。本报告以论文、作者官方项目与代码为主要来源。“代表性”指原始机制贡献以及被后续相关工作讨论，不提供未经核验的引用数排行榜。近期预印本与技术报告的结果按作者报告表述；没有把发布较新等同于影响力已确立。

## 1. 附件 CORAL 的出处与读图

附件对应 Ao Qu 等的 [CORAL: Towards Autonomous Multi-Agent Evolution for Open-Ended Discovery](https://arxiv.org/abs/2604.01658)，2026-04-02 提交；[官方代码仓库](https://github.com/Human-Agent-Society/CORAL)标注 COLM 2026 accepted。机制是长驻 Agent、共享持久知识、异步并行与 heartbeat 反思，评测器独立。论文的限制部分承认依赖强基础模型、同质初始化及预定义评测器等限制。[论文全文](https://arxiv.org/html/2604.01658v1)

图中所有系统使用 Claude Opus 4.6：单 Agent 1350 cycles，四 Agent 1103，先前最好 1363；OpenEvolve 2740。按图上原始数字计算，1363→1103 是约 **19.1% cycles 降低**，而倒数性能分数提高约 **23.6%**。不能把二者混称为精确 20%。四 Agent 为 596 evaluations，单 Agent 56；54/596≈9.1% 的改进率低于 24/56≈42.9%。四 Agent 最优结果更好，不代表每次评测更省或总算力相同。图的时间横轴和外部评测调用数也不能直接等同于模型 token 成本。

同一 HTML 版本的摘要和引言还分别出现“10 tasks”与“8 of 11 tasks”等统计口径；正式复现应固定论文版本、任务清单与预算，不能合并这些数字。图本身证明的是该 kernel 任务上的求解优化；它没有单独证明 Fleet 式源码传代或跨领域自我改进能力加速。

## 2. 代表性与较新工作

理论源头建议先读 Schmidhuber 的 [Gödel Machines（2003）](https://arxiv.org/abs/cs/0309048)：系统在形式化效用与公理下寻找自改有益的证明，再替换自身程序，包括证明搜索器。其最优性依赖可证明性和初始形式系统，不能套用到LLM凭实验结果修改代码。它解释了为什么DGM等后续工作强调以经验验证替代难以实现的形式证明。

另一个应区分的经典邻域是 [MAML（ICML 2017）](https://proceedings.mlr.press/v70/finn17a.html)：把参数训练成能以少量梯度步骤适应新任务。它有助于理解“学会更快学习”的实验目标，但更新对象是模型参数，不是可执行团队代码。本项目应与源码/策略自改工作直接比较，不把MAML列为同条件harness性能基线。这两项作为理论和元学习背景；下表聚焦当前实现最直接的LLM与Agent演化研究。

| 工作、时间、来源 | 实际优化对象与贡献 | 对 Fleet 的价值及比较限制 |
| --- | --- | --- |
| [STOP](https://arxiv.org/abs/2310.02304)，2023-10，Zelikman 等 | 让调用 LM 的代码改进器作用于自身，获得更好的程序改进策略；模型权重固定 | 最直接的“改进器改自己”基线。任务空间较窄，不能用它直接证明长期团队自治 |
| [ADAS](https://arxiv.org/abs/2408.08435)，2024-08，Hu、Lu、Clune | 元 Agent 搜索 Agent 代码与工作流，维护候选档案，报告跨领域/模型迁移 | 应比较固定元控制器下自动设计与 Fleet 的可进化协作机制；“自动设计 Agent”并不新 |
| [Gödel Agent](https://arxiv.org/abs/2410.04444)，2024-10，Yin 等 | 自指 Agent 动态修改自身逻辑，以经验反馈推动策略变化 | 是运行逻辑自改的早期直接相关工作；与冻结候选容器、版本晋升的粒度不同 |
| [SICA: A Self-Improving Coding Agent](https://arxiv.org/abs/2504.15228)，2025-04，Robeyns 等 | coding agent 修改自身代码库；作者报告随机 SWE-bench Verified 子集从17%到53%，另有任务迁移 | 可作为完整 Agent 源码自改的直接基线。这里的百分比属于论文子集，不能与 DGM 的数字作同口径排行榜 |
| [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954)，2025-05，Zhang 等 | 用经验验证替代形式证明，档案树保留多条自改谱系；作者报告 SWE-bench 20→50%、Polyglot 14.2→30.7% | Fleet 目前蓝绿单链有恢复优势，却缺多谱系探索。必须区分工程可靠性与搜索多样性 |
| [AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)，2025-05，Google DeepMind | LM 产生程序，自动评测器评分，演化候选用于数学与系统优化 | 是算法发现的重要代表；优化结果程序与改进 Agent 自身是不同层次，适合借鉴 evaluator-first 和分级筛选 |
| [Huxley-Gödel Machine](https://arxiv.org/abs/2510.21614)，2025-10，Wang 等 | 指出当前任务得分与产生优秀后代的能力不一致，以后代群体表现估计元生产力 | 非常贴近本项目：不能用当前代单次成绩、测试数、晋升率替代未来改进能力。应测后代有效增益/预算 |
| [Hyperagents](https://arxiv.org/abs/2603.19461)，2026-03，Zhang 等 | 任务 Agent 与 meta Agent 共处可编辑程序，连修改机制也可演化，报告跨域积累与迁移 | 最强的直接新颖性约束之一：跨领域、可自改元过程已有人做。Fleet 应把贡献落在团队组织政策与可审计长期实验 |
| [CORAL](https://arxiv.org/abs/2604.01658)，2026-04，Qu 等 | 自主探索、共享知识、异步协作与周期反思 | 提供多 Agent 开放发现的近邻基线；不能仅以共享记忆或频道作为创新 |
| [Mendel Gödel Machine](https://arxiv.org/abs/2608.07645)，2026-08-07，Liu 等 | 同一 Agent 跨任务失败对照，以及不同谱系在同题上的轨迹对照，辅助变异与杂交；理论结论依赖加性适应度模型 | 可用训练轨迹对照替代逐条 anecdote 修复。跨谱系组合需独立集成验证，不能因两个补丁单独通过就接受组合 |
| [Prime Agent](https://arxiv.org/abs/2608.23552)，2026-08-24，Karten 等，技术报告 | 持久 REPL、跨轨迹历史/技能、递归子 Agent 直接通信，标准化恢复、验证与资源核算 | 是较新的 harness 对照对象；“连续上下文+子 Agent+恢复”本身不构成空白。作者性能结果尚不能替代本项目匹配预算的实测 |

不把 self-reflection、记忆积累、prompt 搜索、测试时程序搜索、Agent 自改源码与基础模型权重训练混成一个“RSI”概念。本次工程主要覆盖 Agent/harness 代码与协作政策的代际更新，权重不变。

## 3. 真正有用的缺口

以下为基于文献和旧实验的研究判断，尚非已证明的普遍结论。

### 3.1 通信政策的跨领域可迁移自改

Fleet 已有精确 @、私聊、频道、持久任务和全员 idle 恢复，适合把“何时让谁看到什么”当成可演化变量。关键不是机械少发消息，而是降低没有后续行动价值的通知，同时维持依赖解锁与独立审查。候选政策可调整摘要频率、共享阈值、会议触发、角色分配、读取优先级；不可修改外部评分器和测试划分。

可检验假设：在相同模型、同题和同总预算下，跨任务训练得到的通信政策能降低每个正确任务的消息/token/延迟，而不增加遗漏责任和尾部停摆。与 CORAL、固定模板、多 Agent 无共享记忆以及单 Agent 作匹配对照。若只在训练题变快、测试领域下降，该假设失败。

近邻反例必须纳入：CORAL 附录 C.5–C.7 已包含可调整 heartbeat、会话恢复和独立 grader 超时，因此调节反思频率、自动重启或隔离评测自身都不足以成为新贡献。待验证的增量应限定为通信责任保持的跨域因果证据。[CORAL 全文](https://arxiv.org/html/2604.01658v1)

### 3.2 把恢复能力纳入元生产力

旧实验花大量时间修复自迭代平台，却可能换来后续更多有效探索。值得测量的是故障后能否自主产生、验证和启动下一代，以及单位外部预算能获得多少独立正确的后代改进。可定义训练侧元生产力为：未来 K 代经独立执行验证的任务增益除以这 K 代新增模型与计算成本，同时报告失败代和人工介入。

这不是把 HGM 的思想重新命名；可增加的实证内容是长时故障注入、团队责任转移与恢复延迟，验证这些系统变量如何影响后代改进分布。成本核算必须把构建、重试、闲置、评审和拒绝候选都算入。

### 3.3 训练证据的对照压缩与可追溯继承

把完整历史缩成可检验的记录：失败症状、根因假设、补丁、受影响模块、命令证据、反例、适用领域。优先比较同题不同谱系、同策略不同任务，而不是每代重复叙述所有 evidence。每条记忆保留指向原始训练轨迹的索引；记录它在后代是否被使用及是否减少同类故障。

MGM 已覆盖比较进化，因此本项目的潜在增量是通信/责任轨迹的结构化对照，以及受限上下文下知识保留的因果实验。可以消融掉摘要、引用索引或失败反例，观察错误复发率；不能仅统计 store/recall 次数。

### 3.4 不回流测试的长跑评测协议

需要明确区分 train、validation 与 sealed test。本次按用户要求，周期验证与测试都作为宿主侧观察，结果不进入团队提示、工作树、共享记忆或父代选择。若未来希望用 validation 选模型，应显式改实验协议，同时保留更外层从未参与选择的 sealed test。

每代训练结果可回流以生成修改建议；每 N 代或 T 时间在冻结候选上评测。测试运行使用新容器、新可写状态和只读候选，测试工件写入独立位置。测试题虽需给该轮解题 Agent，但该 Agent 的会话和结果不能继承到训练版本。不同分区按题目族/来源划分，防止改写题泄漏；锁定题目清单和内容哈希，记录公开数据可能已被预训练见过的限制。

Hyperagents 已采用 validation 辅助选择、test 用于最终评测的划分；三分区和测试不回流也并非研究空白。本次进一步不让周期 validation 参与选择，是按用户要求固定的实验协议，不能据此宣称方法天然更先进。[Hyperagents](https://arxiv.org/abs/2603.19461)

## 4. 可执行实验设计

先做无模型基础设施测试：假评分器、超时、中断恢复、数据分区重复检测、跨目录/软链接逃逸、防止测试结果进训练工作区、并发上限与容器归属清理。它能证明控制面行为，不能算 benchmark 成绩。

随后用每域少量真实题跑 baseline 与候选，至少覆盖系统/数据操作（ALE）、数值数学（HorizonMath）、软件修改（后续 SWE 或同等公开任务）。不得把官方数学数据误当成 Lean 形式化证明集；任务协议与评分器必须按官方实现核验。先排除 provider、网络、依赖失败，再做学习效果比较。

正式实验建议分阶段开展，并在启动前固定资源预算：例如 5 个随机种子、20–30 代、每代每域2–4题训练、每5代固定评测。这里是研究设计建议，不是本次已启动的付费任务。对照组至少包含固定 Fleet、只改任务策略、可改协作策略；补充单 Agent、无共享记忆、无对照摘要等消融。尽量复用配对题目与随机种子，并把代际作为相关观测，不能把每条消息当独立样本。

可行性需要先算规模：训练episode数为“种子数×代数×领域数×每域抽样数×对照组数”。5种子、20代、2域、每域2题、3组已是1200次训练episode，还没有计入验证、测试、候选评审与失败重试。应先以1种子、3–5代、小任务数验证可用反馈和真实传代，再据完整容器用量决定正式预算。此次五分钟数学smoke只有Team计量，普通subagent另有轨迹且题目未完成，不能将其token或时间直接外推成正式实验成本。完整核算应遍历该episode全部DSH sessions并与provider用量核对，不能只累加Team成员表。

| 指标 | 解释 | 不能替代它的东西 |
| --- | --- | --- |
| 各领域真实评分及宏平均 | 避免题数多的领域掩盖另一领域退步 | 仅训练总体平均 |
| 正确任务/总预算、score–cost 曲线面积 | 质量与效率同时衡量 | 最优单点得分、调用次数单一指标 |
| actionable 消息占比、责任延迟、重复唤醒率 | 判断交流太多或太少的实际代价 | 总消息少就宣称高效 |
| 人工介入/24h、故障恢复时间、无进展时长 | 判断长跑是否真实自治 | 容器仍 running |
| 未来 K 代有效改进/预算 | 测元改进能力 | 当前代通过率、代码行数、提交数 |
| 域外迁移和密封测试趋势 | 检查过拟合、遗忘与“伪进化” | 团队自己的完成报告 |

得分比较报告区间估计、随机种子、失败分母、预算和模型版本；固定周期查看测试仍可能使人类研究者产生间接选择偏差，因此正式发表实验应预注册停止规则，最终测试只解封一次。日常工程监测可以周期运行，但不得据此宣称严格未触碰测试的研究设计。

## 5. 创新可行性排序

优先推进“可测量的自适应通信+责任保持”，因为已有运行事件与任务状态可直接给出行为证据，实施成本较低。其次推进“故障恢复如何改变元生产力”的长跑实验，它与旧62代记录紧密相关，工程辨识度较高。再次是训练轨迹对照压缩和跨域继承，需要多个可靠 benchmark 与充分预算。暂不把开放修改评测器、权重训练或无限自加速列为本轮成果。

当前代码改进是上述实验的基础设施和若干默认政策修复；在有预算匹配的真实对照结果之前，应描述为“支持验证这些假设”，不能写成“已证明协作质量提升”或“首次实现跨域递归自进化”。
